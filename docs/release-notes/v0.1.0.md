# RunPlay Studio v0.1.0

First product-line release notes for RunPlay Studio — a native macOS post-run
GPS workout visualization, replay, analysis, comparison, and export application.

```text
Release pipeline status: ready
Official binary publication status: not yet published
```

These notes describe the product at marketing version **0.1.0**. They do **not**
claim that a Developer ID–signed, notarized binary has been published until the
owner completes credential-gated production packaging and a GitHub Release.

---

## What it is

RunPlay Studio is a **local-first** desktop studio for completed GPS runs. It is
not a live tracker, cloud service, social network, web app, or AI product.

---

## Headline features

- **Native macOS application** — SwiftUI shell with AppKit/MapKit platform
  adapters and a portable analysis core
- **Local-first privacy** — workouts stay on your Mac; no app-operated backend,
  accounts, telemetry, analytics, or AI APIs
- **Import** — GPX, TCX, JSON, FIT (including multi-session review), and local
  Strava export ZIP archives
- **Persistent workout library** — Application Support storage with favourites,
  rename/notes, tags, and smart collections
- **Application session restoration** — coordinated workspace restore with
  native window frame ownership by macOS
- **Replay** — synchronized map, charts, metrics, and controls
- **Apple Maps** — unified 2D/3D route presentation
- **Charts** — pace, elevation, heart rate, speed with seek interactions
- **Personal Heatmap** — local density of places you run most often
- **Comparison** — Distance alignment and Route-Aware (constrained DTW) mode
- **Exports** — JSON summary, CSV splits/segments, PNG summary card
- **Keyboard and VoiceOver** — menus, shortcuts, and accessibility labels
- **Portable C++23 analysis engine** — bulk kernels for route quality, personal
  heatmap coverage, Route-Aware path solving, and related geometry, with Swift
  owning models, persistence, and UI

## Privacy

- Release and demo bundles contain application code and **synthetic** demo
  resources only
- User workout libraries and session files are **not** part of release artifacts
- MapKit may load map tiles from Apple for map regions you view
- When an official binary is notarized, Apple receives the **app archive** for
  malware scanning — not your workout library

See [privacy.md](../privacy.md).

## Distribution channels

### Demo artifact (when built)

- Produced by `scripts/package-demo.sh` or the Package Demo workflow
- **Unsigned** (or linker ad-hoc only) — **demo/testing only**
- **Not notarized**; may be blocked by Gatekeeper
- Not an official release binary

### Official release artifact (when published)

- Developer ID signed with hardened runtime
- Notarized and stapled
- Gatekeeper-assessed
- Versioned zip: `RunPlayStudio-0.1.0-macos-arm64.zip`
- Accompanied by `SHA256SUMS` and `RunPlayStudio-0.1.0-release.json`

The release pipeline is prepared in-repo; **no official signed release has been
published yet**.

---

## Known limitations

- **arm64 only** — no Intel build in this release train
- **No custom application icon** yet — default executable icon in Finder/Dock
- **No automatic update framework** (no Sparkle / Mac App Store channel in v0.1)
- **No video export**
- **No HealthKit** integration
- **No iOS companion**
- Demo archives remain separate from official release packaging
